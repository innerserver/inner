EMAIL SETUP THAT WILL ACTUALLY SEND

Your old Brevo error means Inner reached Brevo, but Brevo rejected the send because Transactional SMTP/API is not activated on that Brevo account.

Fastest free option: Gmail SMTP
1. Turn on 2-Step Verification for the Gmail account you want to send from.
2. Go to Google Account > Security > App passwords.
3. Create an app password for Mail.
4. In Render > inner > Environment, set:

INNER_EMAIL_FROM=Inner <your-gmail@gmail.com>
INNER_EMAIL_REPLY_TO=your-gmail@gmail.com
INNER_SMTP_HOST=smtp.gmail.com
INNER_SMTP_PORT=465
INNER_SMTP_SECURE=true
INNER_SMTP_USER=your-gmail@gmail.com
INNER_SMTP_PASS=the 16 character Google app password
INNER_REPORT_EMAILS=where-reports-should-go@gmail.com

5. Save changes, then Manual Deploy > Deploy latest commit.
6. In Inner, go to Admin > Server and click Send test email.

Brevo option:
1. Keep BREVO_API_KEY set.
2. Set INNER_EMAIL_FROM=Inner <innerservers@gmail.com>
3. Ask Brevo to activate Transactional SMTP/API. If Brevo still returns 403, Inner cannot force it through.

OPEN SIGNUP SETUP

This build defaults Render to open signup:
INNER_SIGNUP_MODE=open
INNER_REQUIRE_CONTACT=false

If it is still off inside the app:
1. Log in as admin.
2. Go to Admin > Server.
3. Set Signup mode to Open signup.
4. Click Save server.
5. Refresh the login page. The open signup box should say Open signup is on.

If the old behavior stays after deploy, clear the installed app/browser cache or uninstall/reinstall the PWA. This build bumps assets to inner-18 to force a fresh app.js.

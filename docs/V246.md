# Connectifi v246: school workspace

Prepared locally on 15 November 2026. Do not push or deploy until the separate document scanner is provisioned. The live v245 app is unchanged.

## Included

- English, Spanish, French and Hindi interface selection. Preferences are saved per account. Navigation, common labels and the new school controls have translations. Student posts, teacher task instructions, room names and uploaded documents remain in their original language. This does not send private content to an automatic translation provider. Some existing advanced admin messages remain English.
- Teachers/moderators post tasks within an accessible room, with instructions, optional deadline and up to ten reference attachments. Members of that room see them on their dashboard and through **Room tasks** in the message header. Staff can archive their own tasks; admins can archive any task. Deadline labels indicate a date, not whether a student submitted work.
- Admins set events or single-person appointment slots for a selected teacher. Events can target a room or the whole workspace. Members book or cancel their own place. Capacity, teacher appointment overlaps and the member's overlapping bookings are checked on the server. Only admins and the assigned teacher see attendee names.
- Admins can require an explicit acknowledgement on an announcement. Members see a dashboard action; the admin sees names, timestamps and the outstanding audience. Opening a notice does not acknowledge it automatically.
- Forms support file questions, per-question file count/size limits, conditional questions based on an earlier choice, closing dates, explicitly saved private drafts and optional editing before closure. Existing named results and CSV exports remain. A photo capture action appears when the attachment question accepts photos; the device/browser determines whether it opens a camera or file picker.
- Uploads use 2 MiB resumable chunks, confirmed-byte progress, offset/ownership checks, interruption cleanup and idempotent completion. Choose the same file to resume within 24 hours. Only the upload identifier and file fingerprint are retained in browser storage. Staged bytes are private on the app host and can be lost if an ephemeral host restarts. Maximum file size is 250 MiB; unfinished staging defaults to 1 GiB server-wide, configurable with `INNER_UPLOAD_STAGING_BYTES`.
- New school records, saved drafts and acknowledgement-enabled announcements are included in app backups. Sidebar layout, admin accounts/passwords and B2 credentials are unchanged.

## Photo and document policy

Validated JPG/JPEG, PNG, WebP, GIF and HEIC/HEIF photos **skip malware scanning**, as requested. They still undergo size, extension, signature and executable-type checks and are saved outside the public directory without execute permissions. Exemption is selected by the validated file format, not by a client-supplied `image/*` MIME value.

PDFs and all other non-photo uploads require a positive result from a separate ClamAV scanner before their file record is published or their bytes are sent to B2. Missing/unavailable scanner, timeout, detection or incomplete scan causes rejection. New files carry distinct `not-required-photo` and `clean` scan statuses; a photo is never labelled malware-scanned. Existing files are not retroactively scanned.

On a malware detection, the quarantined file and any resumable staging copy are removed and an email is attempted immediately to admin-account email addresses and the configured admin/report contacts. The email includes the uploader, original filename, byte size, timestamp, scanner detection and intended destination: a form and its teacher/moderator, a task's room, or a shared/private file area when no individual recipient was selected. The file is never attached. A missing scanner, encrypted-file policy rejection or scanner size limit is not reported as a confirmed malware detection.

Delivery status is stored in `upload-incidents.json`, included in backups and visible to authorised admins at `GET /api/uploads/security-incidents`. If mail delivery fails, the running app retries with backoff, up to eight attempts. A sent notification is not sent again by the retry worker. This depends on working mail-provider settings and valid admin email addresses; no live email was sent during local tests.

The app streams data using ClamAV INSTREAM and never invokes a shell, executes uploads, extracts their archives or runs document converters. The scanner still parses untrusted bytes; isolation reduces the consequences of a parser vulnerability and does not make an absolute guarantee against exploitation.

## Scanner provisioning, before pushing

The example configuration is in `deploy/scanner/compose.yaml` and `deploy/scanner/clamd.conf`. Docker is not installed in this workspace, so the actual ClamAV container has not been started or verified here.

The scanner runs as the `clamav` user, with all capabilities dropped, no new privileges, a read-only root, a private internal network, no published ports and no mount of app files, app credentials or the Docker socket. Its temporary filesystem has `noexec,nosuid,nodev`; signature databases are mounted read-only. A separate maintenance container updates signatures. Review and pin the scanner image to an approved digest before deployment. The example allows 4 GiB RAM for the scanner.

On an appropriate Docker host, from the scanner directory:

```sh
docker compose --profile maintenance run --rm signature-update
docker compose up -d scanner
```

Join the app container to the same private network and configure:

```text
INNER_CLAMD_HOST=scanner
INNER_CLAMD_PORT=3310
```

A Render deployment needs an equivalent separate private scanner service and its actual internal hostname. These values must not point at a publicly exposed ClamAV port. Do not place B2/MongoDB/mail secrets in the scanner service. Maintain signature updates, restart or reload the daemon after updates, and verify a clean PDF, the standard EICAR test and a rejected/timeout path on the real service before enabling deployment. No paid service has been created.

References: [ClamAV Docker isolation and RAM guidance](https://docs.clamav.net/manual/Installing/Docker.html), [INSTREAM and private TCP requirements](https://docs.clamav.net/manual/Usage/ClamdProtocol.html).

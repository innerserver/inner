# Connectifi v247: Friends and announcement audiences

Prepared locally on 15 November 2026. Includes the local v246 school features and upload policy. Nothing has been pushed; the separate document scanner is still a prerequisite for deployment.

## Friends

- Implemented the approved design with Find people, Your friends and Requests tabs, one search box and actions on each person row.
- Search within your grade by name or username; choose Exact username for another grade. Existing server restrictions still apply. Contact phone numbers and email addresses are not exposed as a public search directory.
- Removed the visible alphabet strip and the duplicated person-selection/add controls. Accepted friends and pending requests appear in their own tabs.
- New queries cancel the previous request. An older response or a response from a previous signed-in account cannot overwrite current results. A query is no longer dropped just because another search is loading.
- Incoming requests have Accept/Decline; outgoing requests have Cancel. The server only lets the sender cancel their pending request.

## Announcements

- The composer offers Whole school, One room and Specific people, with recipient search, removable selections and a live recipient preview.
- Selection is validated against existing available accounts, with at most 400 recipients. Unknown scope values and empty/invalid people lists are rejected rather than becoming a whole-school announcement.
- HTTP state and realtime announcement payloads use the same server-side audience filter. Non-selected members cannot receive targeted notice contents or acknowledgement records. Authorised admins retain oversight.
- Acknowledgements use that same selected audience; an unselected account cannot acknowledge a targeted notice. Admin pending lists refer to the actual recipients. Other recipient usernames are not included in ordinary members' announcement payloads.

## Personalisation

- The new controls use the existing account theme variables for backgrounds, surfaces, text, borders and accent colours. They do not reset profile preferences, replace the personal photo background, change the sidebar or force every account into the same theme.
- Existing custom theme colours, avatar images, light/dark themes and uploaded background images remain available. New file uploads still follow the v246 photo/document policy.
- Photo backgrounds remain behind the workspace, with readable panels over them. No new gradient or forced photo background is introduced by this release.
- English, Spanish, French and Hindi labels were extended for the new actions. Some legacy admin help text remains English, as described in v246.

## Validation

Focused checks cover out-of-order friend searches, switching accounts during search, recipient directory access, selected-person visibility through HTTP state and shared realtime filtering, acknowledgement access, request cancellation, and saving/refetching custom colours and photo backgrounds. Existing school/security/form checks also pass.

The actual new control scripts were rendered locally using sample accounts on desktop/mobile, in light/dark mode and with custom colours plus an existing background image. These renders did not access the signed-in Chrome profile or production data. No real mail was sent and the actual ClamAV service remains unprovisioned.

# Connectifi v248: shared UI and whole-grade discovery

15 November 2026.

## Shared UI

The visual treatment approved for Friends now extends to action buttons, inputs, labels, cards, messages, dialogs and headers across the workspace and sign-in screens. Buttons use a restrained rectangular shape, controls share spacing and type styles, and panels use consistent borders with reduced shadows and decorative effects. Related help/account pages load the same style sheet.

The change is in `public/ui-system.css`. It uses the account's existing palette variables and preserves custom colours, personal photo backgrounds, light/dark modes, compact density and the square-control preference. The sidebar, class-room structure and call/signaling behavior are unchanged. No model-generated photo or new default background is added.

The new stylesheet does not change the workspace/message list scroll dimensions or composer positioning. Local desktop/mobile renders checked that the message composer stays within the active viewport. Hidden sign-in/workspace containers now explicitly remain hidden, fixing an old style conflict that could show the workspace below the mobile sign-in screen.

## Grade versus class

- Grade 9 means 9, 9A, 9B and 9C; the same rule applies to grades 6–12.
- People in 9A can discover and request friends in 9B/9C without knowing an exact username. Name searches work throughout their year.
- People in another year still require exact-username discovery under the existing restrictions.
- A numeric grade filter, such as `grade:9`, includes all sections. An explicit class filter, such as `grade:9B`, remains class-specific.
- Grade-scoped persistent-login and feature-exemption rules follow the same distinction: a rule for 9 includes all sections, while an explicit rule for 9A remains limited to that class.
- Class-specific rooms, attendance and room-task permissions remain separate. Being in the same year does not grant access to another private class room.

Server and browser logic share `public/grade-utils.js` so the Friends list cannot hide sections that the server permits.

## Verification and limits

Focused school, security, search and form regressions passed, including new API checks for cross-section discovery, whole-year versus explicit-section filtering, same-year friend requests, and other-year restrictions. Static local UI renders covered Dashboard, Messages, Files, Profile, Calls, admin controls and mobile sign-in, including light/dark and custom photo themes. No production Chrome profile, camera or microphone was accessed.

This does not change v247's document-scanner requirement. Document uploads need the isolated scanner configured; validated photo uploads retain the requested exemption. No real scanner or live deployment was verified during the UI work.

Training a custom moderation model remains separate. No model training, provider change, new training-data collection or moderation-policy change is included here.

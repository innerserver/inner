# Connectifi v250: passkeys and setup reminders

16 November 2026.

## Sign-in and setup

The sign-in screen now offers Sign in with a passkey. A registered discoverable passkey can authenticate through the device's fingerprint, face, device PIN or security key. Connectifi stores a credential identifier and public key, not the device's private key or biometric data. Password sign-in remains available. This is an alternative sign-in method, not mandatory two-factor authentication for password sign-ins.

After the first successful password login following this release, accounts without a passkey see an optional setup dialog directly inside the workspace. The next reminder follows 20 more successful password logins, then every 20 thereafter. Page refreshes and failed logins do not advance the counter. Existing accounts also see the prompt on their first successful password login after this release. Accounts with a valid registered passkey skip reminders.

Set up passkey starts registration in that dialog. A password authentication within the preceding five minutes permits setup without entering the password again. Otherwise the dialog offers a current-password field. Maybe later closes the dialog. Don't remind me again is a small, readable, keyboard-accessible action in the bottom-right corner. The opt-out is saved per account on the server. Profile offers passkey management and an option to turn setup reminders back on.

Profile supports adding, listing and removing named passkeys, with a maximum of ten per account. Manual profile registration and removal require the current password. A password change/reset invalidates existing passkeys and resets the reminder preference for the new credential identity. Users must add their passkeys again after a password change. Existing passwords and admin provisioning are not modified.

## Security boundaries

Registration and authentication use @simplewebauthn/server 14.1.0. The server verifies the challenge, exact origin, relying-party ID, signed response and user verification. Registration requires a signed-in session and current/recent password verification. Challenges expire after five minutes, are single-use even on verification failure, and registration binds them to the originating session. Pending challenges and route request rates are bounded. Authenticated changes use the existing same-origin and CSRF checks.

Passkey login runs the normal approval, ban, server-lock and session-rotation checks. Public credential lists omit public-key bytes and user handles. New credentials and reminder preferences use the app's existing private persistence and backups. Challenge storage and write serialization have the same single-process scope as sessions. Multi-instance deployments need shared atomic challenge/session storage before scaling out.

## Hosting

Passkeys require HTTPS in production and a supported browser. Loopback localhost development is allowed. Set INNER_PASSKEY_ORIGIN to the exact public origin, for example https://connectifi.in, if it differs from INNER_PUBLIC_URL/PUBLIC_URL or the production fallback https://connectifi.in. The origin must have no path, query or credentials. Passkeys for one hostname do not automatically work on a different www or Render hostname. Keep the public origin stable.

No email OTP provider is required or added. Registering a real device passkey remains a user action. Local checks use synthetic WebAuthn credentials and signed assertions, not a production biometric/device test. A source push does not verify deployment on Render.

References: https://simplewebauthn.dev/docs/packages/server/ and https://developers.google.com/identity/passkeys/developer-guides/server-registration

# Connectifi v251: grade promotion and graduation

16 November 2026.

## Normal Admin panel

The normal Admin panel has Admin controls and Update grades tabs. Update grades is not an owner-only section. Existing built-in administrative accounts with normal Admin access, including admin2, can preview and approve promotion. Teachers/moderators and members cannot access the administration API. No sidebar layout or admin credentials are changed.

Choose an academic year such as 2026-2027 and either all grades or one source grade. Preview shuffle uses the original source roster and a cryptographic random shuffle to assign the next grade's A/B/C classes. Counts differ by at most one for each promoted grade. The preview lists every username, original class and new class, including the Grade 12 graduation list. Random shuffling balances counts only, not academic performance or gender. A new shuffle can coincidentally keep some classmates together.

Preview changes no accounts. The admin reviews the roster, checks an approval box, then clicks Approve and update grades. Only that explicit approval applies the plan. The server takes a backup first. Each student can move once per selected academic year, so an all-grades update does not cascade a student through several grades. Newly promoted Grade 12 students do not graduate in that same cycle. Already-graduating accounts and staff/admin accounts are excluded.

Previews expire after 30 minutes and are rejected if the roster changes. Approval is serialized against other account writes. The durable journal protects academic changes from old in-flight account snapshots, supports retry without double promotion and recovers an interrupted apply on startup or the next sweep. These queues have the same single-process deployment scope as sessions; multiple replicas require shared atomic coordination.

After approval, profile grade, active session grades and numeric-grade/legacy-section memberships update together. WebSocket and HTTP fallback clients receive class updates. Old room messages remain under their original access rules. Future whole-grade announcements follow the new grade room.

## Grade 12 export month

Approving a plan containing current Grade 12 students starts one calendar month of continued account access. For example, approval on 16 November at a particular UTC time schedules deletion for 16 December at that time. Month ends clamp to the last valid day of the next month. This is a calendar month, not a fixed 30-day duration.

The member dashboard displays the exact local deadline and Export my chats. The JSON download contains currently accessible stored room messages and the user's participating DMs. Other private rooms and other people's DMs remain excluded. Attachments appear as references rather than bundled file bytes, so members must download files separately before the deadline. Deleted/expired history is unavailable.

The app checks the deadline on sign-in, session access and realtime traffic. A cleanup worker runs at startup and every minute while the server runs. It deletes expired member accounts, revokes sessions, removes registered passkeys and preferences, removes profile/personal-pin records, removes friend relationships and pending account requests, and removes room memberships. Durable tombstones prevent old account snapshots from restoring the deleted credentials. If the host sleeps, actual record cleanup happens when it next runs; login/session checks still reject expired access when serving requests.

This deletes the account, not every historical mention or shared message. Existing shared chat messages, file records and backups follow the app's existing retention policy. Backups contain sensitive records and an explicit full restore can roll back state. No claim of permanent personal-data erasure is made.

## Verification

Focused checks cover admin2 access, member/moderator denial, CSRF, balanced rosters, preview-only behavior, source-grade isolation, once-per-year promotion, stale/expired previews, room/session updates, restricted exports, calendar-month deadlines, credential deletion, stale-write protection and interrupted-approval recovery. Local desktop/mobile renders exercise the real tab/preview/approval controls using sample data. No live student accounts were promoted or deleted during development.

The presentation is an output artifact outside the source repository. UI proposals from v249 remain proposals. The document scanner dependency and unresolved real-device screen-sharing verification remain unchanged.

# Connectifi v252: cleanup, newcomers and questionnaire identity

16 November 2026.

## Approved cleanup

Removed the old implementation bodies after the two direct-Cloudinary endpoints' unconditional 410 responses. Their URLs, status codes and error messages remain unchanged. Removed the constant-false disk-avoidance upload branch. Active file validation, quarantine/scanning, B2 uploads and legacy provider/file-download support remain.

Removed unused personal-pin helpers, state initialization and hydration from the browser. The shared Pin/Unpin controls remain. Server personal-pin endpoints and existing saved records remain for compatibility. Removed the unused writeUsers dependency passed into grade progression; the active exclusiveUsers transaction and commit callback remain responsible for account writes.

## New students and destination class counts

New students can join a grade through the existing account/profile flow and grade-room synchronization. A student without a promotion marker for the selected academic year can appear in a subsequent promotion preview, while students already promoted for that year retain their placement.

New allocations now count active students already staying in the destination classes. Students leaving the destination grade in the same plan, and accounts already in their graduation export period, do not count as remaining class members. After randomly shuffling the incoming cohort, each assignment chooses the currently smallest class, using A/B/C order for ties. With empty destination classes this preserves the previous round-robin allocation behavior. Existing students are not reshuffled.

The preview shows total destination class sizes after the update. Differences of up to three are acceptable under the updated requirement. When a pre-existing imbalance still exceeds three after placing newcomers, the preview explicitly warns rather than silently moving existing students. Balancing an already-unbalanced roster may require a separate approved reassignment; no guarantee is made that adding a small cohort can correct every existing imbalance.

The preview fingerprint now also covers destination students and their relevant enrollment state. A roster change requires a fresh preview. Expiry, approval, per-year guards, backup and recovery remain in place.

## Automatic questionnaire identity

New forms record createdBy and createdByGrade from the sender's current server account, ignoring client-supplied identity fields. The sender class is a snapshot at creation and remains unchanged if the sender later changes class. It can be staff or blank when that is the configured account grade; a teaching class is not invented from the selected audience.

The form list, response dialog and results display the sender and class when recorded. CSV exports retain existing columns and append Form sender and Sender class. Old forms without a recorded sender class continue to work without a fabricated historical value.

Responses already recorded the signed-in respondent username and current class server-side. Focused checks now explicitly verify that forged browser username/grade values do not override those fields.

# Connectifi v256: passkey autofill

17 November 2026.

## Sign-in behavior

The username field now carries autocomplete="username webauthn" and receives focus on returning to sign-in. Supported HTTPS browsers start a conditional WebAuthn request and can offer saved Connectifi passkeys with their native autofill suggestions. Selecting a passkey invokes the device/browser's verification flow, such as Windows Hello, macOS Touch ID or the configured credential provider. Browser settings and support control the exact presentation. The app does not enumerate saved device credentials, force a native modal on every page load, or sign anyone in without selection and verification.

Password sign-in and the explicit Sign in with a passkey button remain. Unsupported browsers, no saved credential and cancellation stay quiet during conditional autofill. Actual verification failures after selection display feedback. Existing registration, reminder preferences and server authentication checks remain unchanged.

## Request coordination

Password submission cancels and waits for pending autofill before proceeding. Explicit passkey sign-in does the same before opening its normal prompt. Simultaneous credential verification and password/explicit passkey submissions cannot proceed together. Autofill stops while the login view is hidden, during signup/password reset, when the document is hidden, and on navigation. Returning to sign-in or focusing the username field can restart it. A four-minute renewal replaces an outstanding challenge before the server's existing five-minute expiry.

# Connectifi v258: passkey prompt and control finishes

17 November 2026.

## Passkey sign-in

v256 requested conditional WebAuthn autofill. This waits for selection in the username field and does not itself request a modal device prompt. v258 additionally attempts one standard WebAuthn prompt after the application confirms the sign-in screen should be shown, when the browser reports a platform authenticator is available. This capability does not prove a Connectifi passkey exists on the device. The browser and operating system still control whether a prompt appears, and keys must belong to the current Connectifi relying-party domain.

Automatic and conditional requests are serialized with the same abort controller and challenge lifecycle. Dismissing the automatic prompt resumes quiet autofill without repeated modal prompts. Password submission cancels pending authentication first. Explicit logout suppresses automatic prompting, preventing an immediate sign-in prompt after signing out. The explicit passkey button remains available, including for external security keys and browsers that do not expose platform capability. An inline hint explains the fallback. Server signature checks, required user verification, challenge expiry, account restrictions and session rotation are unchanged.

## Buttons and menus

A final controls stylesheet adds restrained border and shadow detail, consistent button typography, pressed feedback and visible keyboard focus. Existing colour palettes, density, square-corner preference and Glass photo layers remain in use. Sidebar dimensions and layout rules are unchanged.

Single-value dropdowns use the browser's customizable select API where supported, styling the actual open menu, options, selection checkmark, optgroup headings, scrolling and focus. The browser retains native labels, keyboard/typeahead, form validation, option updates and change events. Multi-select and listbox controls retain their existing behavior. Browsers without `appearance: base-select` retain the functional native picker. Message action and attachment/tool panels receive matching themed surfaces.

## Focused verification

23 client/server passkey checks pass, including automatic prompt selection, cancellation fallback, explicit logout suppression, password interruption, signed assertions and rejected forged assertions. Isolated local Chrome desktop/mobile previews verify the actual customized picker, keyboard selection, change events, required validation, dynamic options, Escape, mobile width and unchanged sidebar dimensions. Native Windows Hello, Touch ID and the user's stored passkeys were not accessed or verified. No signed-in browser debugging or full audit was performed.

# Connectifi v260: local document study notes

17 November 2026.

Files now has Make study notes, and supported uploaded files have Make notes. Choose a local document or read an existing file through its normal authenticated download route. Supports PPTX (presentation slide order and associated speaker notes), text-based PDF (page references), DOCX, UTF-8 TXT, Markdown and CSV. Old binary PPT/DOC files must be converted first. Image-only scans, embedded pictures/charts and recorded audio are not transcribed.

Source notes work without any model download. Brief/Standard/Detailed controls select source sentences and show key terms, original references and expandable source text. Copy or download notes as plain text. Documents and notes are processed in browser workers and are not uploaded to a model service or saved as new server records. Existing shared files are fetched from Connectifi with existing permissions, including the B2 proxy. Local documents selected here are not uploaded to Connectifi.

Optional AI downloads the Apache-2.0 Xenova/flan-t5-small model at pinned revision 311454e83bc784267fd7eef5940ee854144abbec. The encoder/decoder downloads in the smoke test totalled about 92 MB, plus supporting files. Inference runs on the device using the bundled WASM runtime, without API keys, hosted inference, subscriptions, trial quotas or a paid fallback. Browser model caching is used when available; browsers may evict cached files. Existing internet/device/Connectifi hosting costs remain. There is no guarantee that a third-party download host remains available forever. No new model was trained.

Small-model generated summaries were unreliable in the smoke test. AI mode therefore uses the draft only to rank original source sentences; displayed AI-selected points contain source wording rather than raw generated claims. This reduces invented wording but can still omit context. English works best for the model. Source extraction retains Unicode text.

Limits: 25 MB input; 100 pages/slides/sections; 200,000 extracted characters; 2 MB per relevant Office XML part; 8 MB total selected expanded XML; 2,000 ZIP entries. XML DTD/entity declarations are rejected. Documents are parsed as data, never inserted as HTML or executed. PDF evaluation and WASM decoding are disabled. Processing can be stopped, has timeouts and is terminated on dialog close or logout. This does not replace the existing upload validation/scanner.

The normal page CSP remains unchanged. Only /study-notes/ai-worker.js gets wasm-unsafe-eval to compile the local WASM runtime; it does not allow JavaScript unsafe-eval. Model worker connections are restricted to same-origin assets and Hugging Face download hosts. Local .mjs/.wasm runtime assets have the correct MIME types; uploaded executable extensions remain blocked. Runtime assets are bundled, not remotely imported scripts. Dependency versions and model revision are pinned; third-party licence notices ship in public/vendor/study-notes/THIRD_PARTY_NOTICES.md. Rebuild with npm ci --prefix tools/study-notes --ignore-scripts --no-audit --no-fund, then node tools/study-notes/build.mjs. Render does not need these build dependencies installed because generated assets are included.

Verification: seven focused automated checks cover type/size restrictions, source grounding, Office extraction/order/speaker notes, XML rejection, ZIP expansion limits and empty text. Isolated local Chrome checks cover the real PDF worker under the application security headers, source notes desktop/mobile UI, sign-out cleanup and actual model download/inference. The model's raw output was deliberately not trusted. No user browser profile, real student files, paid API or full audit was used.

Progress bars inside Study notes show actual processed PDF pages, downloaded bytes and completed AI text chunks. The available Codex pet tools expose selection, metadata and artwork updates, but no live task-progress overlay. No pet artwork or Codex installation files were modified to simulate one. Sidebar layout is unchanged.

# Connectifi v262: startup transfer and remembered login colours

24 November 2026.

## Faster asset delivery

Local static JS, module JS, CSS, HTML, JSON and SVG files between 1 KB and 2 MB are gzip-compressed when the browser accepts gzip. The server caches compressed representations with a 32-entry/8 MB bound and invalidates them when size/mtime changes. Compression runs asynchronously. ETag revalidation returns 304 without a response body for unchanged assets. HEAD returns headers without a body. Vary: Accept-Encoding separates cached representations. gzip;q=0 is respected.

The normal same-origin security headers and content types remain. This path applies only to public static assets; API data and authenticated uploads do not enter the compressed asset cache. Large model/runtime binaries remain streamed through the existing static path. No immutable cache lifetime is used, avoiding stale releases.

Measured local payload sizes with gzip level 6:

| File | Raw bytes | Compressed bytes |
| --- | ---: | ---: |
| app.js | 449632 | 97267 |
| styles.css | 173650 | 27811 |
| index.html | 115091 | 21526 |

These three assets total 738373 raw bytes and 146604 compressed bytes, approximately 80% less. This is a transfer-size measurement, not a measured reduction in live Render load time. Render may already compress some responses at its edge; cold starts, database/network latency and device speed still affect real startup time.

Games and Google Workspace iframes no longer have eager initial src URLs in the HTML. Games initialize when their view opens; hidden render/customization passes no longer navigate the game iframe. Google Workspace already initializes when opened. All frames additionally carry loading=lazy. This avoids starting those third-party pages when users only open login/dashboard.

## Last applied palette on login

A small same-origin head script restores the remembered palette before first paint. Logged-in theme application remembers the effective preset/custom colours, including the current accent foreground. Logout and a fresh signed-out page restore these colours instead of forcing the default light palette. Starting another authenticated session clears the temporary login overrides before applying that account's appearance.

The device-local cache contains only a validated theme name, colour mode and nine whitelisted colour tokens. It contains no username, session, photo or wallpaper URL. Corrupt/unavailable storage is ignored safely. Account wallpaper still clears on logout; it remains available in the signed-in workspace. Shared-device users will see the previous palette. Custom colours are included, but the personal photograph is not shown on login.

## Verification

35 focused checks pass: compression round-trip, gzip negotiation, HEAD/304 behavior, palette validation/clearing, existing appearance/contrast checks and school/profile persistence regressions. Isolated local Chrome verification confirmed gzip Content-Length=97267 for app.js and a subsequent 304, remembered dark colours in a fresh signed-out browser context, and preserved wallpaper/sticky-save behavior. These are local fixtures, not the user's signed-in browser. No new full audit was run.

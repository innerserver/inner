# Connectifi v265: optional Google sign-in

Google sign-in is available for existing accounts whose saved email uniquely matches a verified Gmail or Google Workspace identity. It does not register accounts or accept a role from Google. Existing approval, ban, graduation, continuity and shutdown restrictions apply through the shared login function. Passwords and passkeys remain available. Accounts using other email providers continue to use those methods.

The server uses Google's official authentication library for code exchange and ID-token verification. Each attempt has a ten-minute, single-use browser-bound state, nonce and PKCE verifier. The flow cookie is HttpOnly and SameSite=Lax, and Secure on HTTPS. Successful login preserves the flow-cookie deletion alongside the session cookie. Tokens and client secrets are not returned to front-end code. A server restart ends pending Google sign-in attempts.

## Activation still required

Create a Google OAuth web application client. Register this exact production redirect URI:

`https://connectifi.in/api/auth/google/callback`

Set these server-side Render environment variables, then redeploy:

* `INNER_GOOGLE_CLIENT_ID`: the web application's client ID.
* `INNER_GOOGLE_CLIENT_SECRET`: its secret, never committed to Git.
* `INNER_GOOGLE_REDIRECT_URI`: the redirect URI above.

Use only `openid` and `email` scopes. Configure Google's consent audience and authorized domain for the intended school users. If the consent application is in testing mode, add the permitted test accounts in Google Console. The login button stays hidden when configuration is missing. No live OAuth client, consent configuration or Render secret was created during this pass. Real-provider end-to-end login remains unverified. Sessions and pending OAuth attempts are in memory, so multi-instance hosting needs shared state or reliable instance affinity before enabling this flow.

## Mail setup findings

Cloudflare CLI authorization succeeded. Public MX records already point to Cloudflare Email Routing. A Cloudflare D1 database named mailflare exists but has zero tables. No DNS, routing, mailbox, subscription or billing changes were applied.

Mailflare Community is free for solo self-hosting. Separate user accounts and shared mailbox access require its paid Team license. This conflicts with the requested free private mailbox for every person, so a mail topology decision is pending. Free forwarding to people's existing inboxes does not provide private webmail at mail.connectifi.in. Resend is for outbound app mail within its plan limits; it is not each person's hosted inbox. Hosting and storage quotas can incur costs if paid services are enabled. No promise of unlimited free email is made.

Provider references: https://mailflare.co/ and https://resend.com/pricing
